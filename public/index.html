Set Up Port Forwarding

Until these ports are opened on your router, only people on your own network can connect. You do this once per server.

Open these ports —
Forward them to this machine
  1. Open your router's settings page in a browser — usually 192.168.1.1 or 192.168.0.1.
  2. Sign in. The password is often printed on a sticker on the router itself.
  3. Find Port Forwarding. Routers file it under Advanced, NAT, Virtual Server, or Gaming.
  4. Add one rule per port above. Set the internal and external port to the same number, point it at the address above, and match the protocol (UDP or TCP).
  5. Save. Some routers restart themselves before the rules take effect.

Setup

This dashboard drives real Windows services, and the setup steps need administrator rights. The fastest route is to hand the prompts below to a coding agent — Claude Code, Cursor, Copilot — opened in this repository. The repo's docs are written to be followed by one.

Before you start
  • Windows 10 or 11, with an account that can run things as administrator.
  • Node.js 18 or newer.
  • NSSM — runs each game server as a Windows service.
  • SteamCMD — only for Steam-based games.
First — install and configure

Run once, on the machine that will host the servers.

Read AGENTS.md and docs/SETUP.md in this repository, then set this dashboard up on my Windows machine.

Check which prerequisites I'm missing (Node 18+, NSSM, SteamCMD) and tell me how to install them. Create config.json from config.example.json and fill in my LAN address, public address, and the paths to nssm.exe and steamcmd.exe.

Registering Windows services and adding firewall rules needs elevation, and the dashboard runs unelevated. Do not try to run those yourself — give me the exact commands and I'll run them in an admin terminal.
Then — add a game server

Replace the game name. Repeat for each game you want to host.

Read docs/ADDING_GAMES.md and AGENTS.md, then add a VALHEIM server to this dashboard.

Install the server files, register it as a Windows service with NSSM, and add its entry to the servers array in config.json — including the correct processName (for Unreal games this is the *-Win64-Shipping-Cmd.exe process, not the launcher), queryPort, queryProtocol, and ports.

Give me any elevated commands to run myself rather than running them for me. When you're done, tell me which ports I need to forward on my router.
If something breaks

Describe the symptom where indicated.

Read docs/TROUBLESHOOTING.md and AGENTS.md in this repository.

Problem: DESCRIBE WHAT'S HAPPENING HERE.

Diagnose it against the known failure modes in the docs first. This manages live game servers that people may be playing on, so verify against a stopped server before changing anything that's running, and tell me what you're going to do before you do it.
Reference
  • docs/SETUP.md — first install, config reference, running as a service
  • docs/ADDING_GAMES.md — per-game reference values
  • docs/TROUBLESHOOTING.md — known failure modes
  • AGENTS.md — architecture and the invariants that must not be broken

This dashboard has no authentication. Keep it on your LAN. Don't port forward port 8080 itself — use Tailscale, WireGuard, or a Cloudflare Tunnel to reach it from outside.
